## 2. 根因（三层）

### 2.1 框架层：`setRegisterHost` 只作用于 service，没作用于 topic

框架里"对外通告地址"有 **3 个使用点**，只有 1 个走了解析链：

| 使用点 | 代码位置 | 原实现 | 结果 |
|--------|---------|--------|------|
| service 注册 | `runtime_service.cpp:79` | `resolveRegisterHost(service, listenerAdvertiseHost())` | ✅ 板 IP |
| **topic 首次发布** | **`runtime_topic.cpp:132`** | **`listenerAdvertiseHost()`** | ❌ **恒 127.0.0.1** |
| **topic SM 重连恢复** | **`runtime_sm.cpp:433`** | **`listenerAdvertiseHost()`** | ❌ **恒 127.0.0.1** |

而 `listenerAdvertiseHost()` 是写死的：

```cpp
std::string OmniRuntime::Impl::listenerAdvertiseHost() const {
    return normalizeAdvertiseHost("0.0.0.0");   // → "127.0.0.1"
}
```

### 2.2 协议层：TCP 半帧会永久破坏字节流

```
sendAll() 失败时可能已写入 N 个字节（半帧）
  → 对端按"长度前缀 + body"解析 ⇒ 从这半帧开始永久错位
  → 不是"丢一帧"，而是"后续全部解析错乱"
SHM 为整帧原子写 ⇒ 无此问题
```

原实现：发送失败只打日志并 `return false`，**连接继续复用** ⇒ 一旦半帧发生，该连接就废了但没人回收。

### 2.3 为什么板内一直正常

板内 `media_proc → face_proc` 的订阅走 **SHM**（同机），**不读 `pub_info.host`** ⇒ 地址错误对板内无影响，因此该缺陷长期被掩盖。

## 3. 修复内容（3 处，逐项：为什么 / 怎么改）

### 3.1 【地址】`runtime_topic.cpp:132` — topic 首次发布

**为什么**：`pub_info` 是发给 SM 的"发布者信息"，SM 会把它转给所有订阅者。地址错 ⇒ 所有跨机订阅者连到本机。

**怎么改**（照抄上游 `9dbdb49`）：

```cpp
// 改前
pub_info.host = listenerAdvertiseHost();
// 改后
pub_info.host = resolveRegisterHost(entry->service, listenerAdvertiseHost());
```

`resolveRegisterHost` 的优先级：`service 级 setRegisterHost > runtime 级 setRegisterHost > 监听地址回退`。因此**已设 `FACE_REGISTER_HOST` 的进程立刻生效，未设的行为不变**（回落到 `normalizeAdvertiseHost`）。

### 3.2 【地址】`runtime_sm.cpp:433` — SM 重连后重发 publish_topic

**为什么**：SM 重连时框架会重放 `MSG_PUBLISH_TOPIC`。若这里仍用监听地址，**SM 每次重连都会把发布者地址重置回 127.0.0.1**（跨机连接会周期性失效）。

**怎么改**（**本项目自研**，上游无对应 hunk）：

```cpp
// 改前
pub_info.host = listenerAdvertiseHost();
// 改后
pub_info.host = resolveRegisterHost(sit->second->service, listenerAdvertiseHost());
```

> ⚠ 上游**没有**这处改动的原因见 §5.3：上游在更早的 `4aee06b`（服务实例身份重构，162 文件）里**把这行整个删掉**，改为按 `instance_id` 寻址。那套改法无法照抄，故这里按"与 3.1 同义"的方式自研。

### 3.3 【半帧】`connection_manager.cpp`（2 个函数）

**为什么**：PC 日志中的 `sendAll() incomplete bytes=34` 正是半帧场景；不回收连接 ⇒ 后续帧全部错位。

**怎么改**（适配上游 `9dbdb49`）：

```cpp
// sendRawWithDeadline / sendRawWithinTimeout 的失败分支
if (sendAll(...) != 0) {
    const bool tcp = (conn->transport->type() == TransportType::TCP);
    const std::string svc = conn->service_name;   // ← 本地字段名（上游为 connection_key）
    OMNI_LOG_WARN(..., svc.c_str(), ...);         // 用副本打日志（failConnection 可能触发 removeConnection）
    if (tcp) {
        failConnection(conn);   // 摘 fd + 断开回调触发重连
    }
    return false;
}
```

**适配点**：本地版本该字段叫 `service_name`（上游叫 `connection_key`），所以**先存副本再打日志**，避免 `failConnection` 触发 `removeConnection` 后解引用悬垂 `conn`（`failConnection` 内部的注释已明确"回调链可能删除该连接"）。

| 项 | 值 |
