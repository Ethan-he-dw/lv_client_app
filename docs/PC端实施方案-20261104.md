## 1. 已核实的事实（本机实测，勿照抄对接文档）

对接文档的示例 API 与实际生成产物有 4 处不一致，**本方案以实测为准**：

| # | 对接文档写法 | 实测结果 | 影响 |
|---|---|---|---|
| 1 | `omni-idlc -i x.bidl -I idl/ -o dir --cpp` | **`omni-idlc <文件> --output=<dir> --lang=cpp`**（无 `-i/-I/-o`） | 照抄直接报 `Unknown option` |
| 2 | 产物只有 `face_service.bidl.h` | 生成 **4 个文件**：`face_service.bidl.{h,cpp}` + `common_types.bidl.{h,cpp}` | 只编 `.h` 会缺 `serialize/deserialize/interfaceInfo` → **链接失败** |
| 3 | `omnibinder::FaceResult` | 实际命名空间 **`mediaipc::`**（IDL `package mediaipc`） | 编译报"未声明" |
| 4 | `subscribeTopic(name, cb)` | 实际 **4 参**：`(name, expected_idl_hash, on_msg, on_err)`；生成的 `SubscribeFaceResult(cb)` 内部把 `on_err` 传 `nullptr` | 想拿到 IDL 不匹配告警，不能只用生成的包装 |

另外三条关键的运行时事实：

| 事实 | 依据 | 对设计的影响 |
|---|---|---|
| **订阅不依赖 `connect()`** | 生成代码 `SubscribeFaceResult` 只调 `runtime_.subscribeTopic(...)` | 可以不调 `proxy.connect()`；connect 只影响 RPC 与死亡回调 |
| **发布者离线时订阅仍返回 0** | `runtime.h:184` "发布者尚未上线时订阅成功…不匹配则经 on_err 通知" | "订阅成功" ≠ "服务在"，判活只能靠**有没有数据** |
| **`stop()` 是终态，`init()` 只能成功一次** | `omni_runtime.cpp:298` 注释 + `initialized_` 校验 | **每次重试必须新建 `OmniRuntime` 实例**，不能复用 |

已确认可用的 API（生成头实测）：

```cpp
namespace mediaipc {
struct FaceDet  { float score, x1, y1, x2, y2; std::vector<float> kps; };

struct FaceResult {
    uint64_t seq; uint32_t buffer_id, det_count;
    std::vector<FaceDet> dets; FaceItem best; int32_t best_index;
    float score_thr, match_thr; FacePerf perf; uint64_t ts_us;
    static const uint32_t TOPIC_IDL_HASH = 0x368f4259u;
};
class FaceServiceProxy : public omnibinder::ServiceProxyBase {
    FaceServiceProxy(omnibinder::OmniRuntime&);
    int SubscribeFaceResult(const std::function<void(const FaceResult&)>&);
    int GetStatus(int32_t&); int GetFrameCount(int32_t&);
};
}
// 运行时

void OmniRuntime::run();          // 阻塞直到 stop()

int  OmniRuntime::subscribeTopic(name, hash, TopicCallback, TopicErrorCallback);
typedef std::function<void(uint32_t, const Buffer&)> TopicCallback;
typedef std::function<void(uint32_t, ErrorCode, const Buffer&)> TopicErrorCallback;
```

## 3. 数据契约：`face_result_t`（定长、C 友好）

**为什么不用 C++ 类型**：UI 层是 C，`std::vector<std::string>` 过不了 C 边界；且每帧 25 次堆分配没必要。

```c
#define FACE_MAX_DETS   16     /* 与板端 kMaxBoxes 对齐，超出截断 */
#define FACE_MAX_KPS    10     /* 5 点 × (x,y) */
#define FACE_NAME_MAX   32     /* 姓名是字母/编号，32 足够 */
#define FACE_MAX_ALTS   4

typedef struct {
    float score, x1, y1, x2, y2;
    float kps[FACE_MAX_KPS];
    uint8_t kps_n;              /* 0 或 10（板端可能为空） */
} face_det_t;

typedef struct { char name[FACE_NAME_MAX]; float cosine; } face_alt_t;

typedef struct {
    uint64_t seq;
    uint32_t det_count;         /* 已按 FACE_MAX_DETS 截断 */
    int32_t  best_index;        /* <0 表示无 best */

    face_det_t dets[FACE_MAX_DETS];

    char    best_name[FACE_NAME_MAX];
    uint8_t best_matched;       /* bool，避免 C/C++ bool 尺寸差异 */
    float   best_cosine;

    face_alt_t alts[FACE_MAX_ALTS];
    uint8_t    alt_n;

    float fps, det_ms, mbf_ms, dec_ms;
    float score_thr, match_thr;
    uint64_t ts_us;             /* 板端单调时钟，只能算相对时间 */
} face_result_t;
```

**转换规则**（`face_src_omnibinder.cpp` 内一个 `ToCFace()`）：

| 项 | 规则 |
|---|---|
| `det_count` | `min(msg.det_count, FACE_MAX_DETS)`，同时与 `msg.dets.size()` 取小 |
| `kps` | `size()==10` 才拷，否则 `kps_n=0`（下游按缺失处理，不画点） |
| `name` | `strncpy` + 强制 `'\0'`；空串就是空串 |
| `best_index` | 原样（`<0` 时 OSD 不高亮任何框） |
| `alts` | 取前 4 个 |

## 4. 抽象层：`face_source.h`

```c
typedef enum {
    FACE_IDLE = 0, FACE_CONNECTING, FACE_SUBSCRIBED,
    FACE_STREAMING, FACE_NODATA, FACE_FAILED
} face_state_t;

typedef struct face_source_ops {
    const char *name;
    int  (*open)(const char *host, int port);   /* 立即返回，内部起线程 */
    void (*close)(void);                        /* 幂等，可被 UI 线程调 */
    face_state_t (*state)(void);                /* 线程安全；NODATA 由超时推导 */
    bool (*latest)(face_result_t *out, uint32_t *ver);
    const char *(*last_error)(void);            /* 失败原因文本，给面板/日志 */
} face_source_ops_t;

const face_source_ops_t *face_source_active(void);   /* 单例，编译期选定 */

/* 便捷包装（UI 只需这四个） */
int          face_open(const char *host, int port);
void         face_close(void);
face_state_t face_state(void);
bool         face_latest(face_result_t *out, uint32_t *ver);
```

**契约（写进头注释，实现必须遵守）**：

1. `open()` 立即返回；连接/订阅在内部线程
2. `state()` / `latest()` 任意线程可调，内部加锁
3. 实现内部**禁止任何 `lv_*`**
4. `close()` 幂等，且必须能打断阻塞中的等待
5. `ver` 只在新帧时递增
6. **单例**：`open()` 时若已有会话，先内部 `close()`

`FACE_NODATA` 不单独存储，由 `state()` 惰性推导：`SUBSCRIBED/STREAMING` 且 `now-last_rx > 3000ms` → 返回 `NODATA`。这样不需要额外看门狗线程。

## 5. 实现 A：`face_src_omnibinder.cpp`（真机）

### 5.1 结构

```cpp
namespace {
struct Session {
    std::thread                ctl, drv;      /* ctl=控制面，drv=事件循环 */
    std::atomic<bool>          stop{false};
    omnibinder::OmniRuntime   *rt{nullptr};   /* 每轮重试新建 */
    std::atomic<int>           state{FACE_IDLE};
    std::atomic<int64_t>       last_rx_ms{0};
    std::atomic<uint32_t>      rx_count{0};
    std::atomic<int>           last_err{0};
    std::mutex                 err_mu;
    char                       err_txt[128]{0};
};
Session *g_s{nullptr};                        /* 单例 */
}
```

### 5.2 线程时序（关键：谁在哪个线程做什么）

```
open(host, port)  ── 起 ctl 线程，立即返回
      │
      ├─ ctl 线程：for attempt = 0..9
      │     rt = new OmniRuntime                  // ★ 每轮新建，不可复用
      │     if (rt->init(host, 9900) != 0)  → 释放 + backoff + continue
      │     drv = thread([rt]{ rt->run(); })      // ★ 先起驱动
      │     等 drv 就绪（轮询 rt->isRunning()，≤500ms）
      │     if (lookupService("FaceService", info) != 0) → teardown + backoff
      │     if (subscribeTopic(...) != 0)               → teardown + backoff
      │     state = SUBSCRIBED；ctl 退出（drv 继续泵）
      │   state = FAILED（10 次用尽）
      │
      └─ drv 线程：rt->run()  阻塞，直到 close() 里 rt->stop()
            └─ TopicCallback（在 drv 线程执行）
                 只做四件事：转 face_result_t → store_put → last_rx=now → state=STREAMING
```

**为什么不能省掉 ctl 线程**：`init/lookup/subscribe` 都是同步阻塞 API，必须有人泵 `event-loop` 才能返回；而 `run()` 阻塞。所以"先起 drv，再在 ctl 调同步 API"。框架文档明确"不建议在 owner event-loop 回调中发起同步 API"。

### 5.3 订阅：用 `subscribeTopic` 而不是生成的 `SubscribeFaceResult`

生成包装把 `on_err` 写死为 `nullptr`，那样 **IDL 不匹配只能表现为"永远没数据"**，从 UI 上无法与"没人脸"区分。我们直接调 4 参版本，仍然用生成类型与常量，不手写魔法值：

```cpp
const int rc = rt->subscribeTopic(
    "FaceResult", mediaipc::FaceResult::TOPIC_IDL_HASH,
    [](uint32_t /*tid*/, const omnibinder::Buffer &data) {
        mediaipc::FaceResult msg;
        omnibinder::Buffer buf(data.data(), data.size());
        if (!msg.deserialize(buf)) return;      /* 解析失败静默丢弃 */
        OnFaceResult(msg);                       /* 只写槽，见 5.2 */
    },
    [](uint32_t /*tid*/, omnibinder::ErrorCode err, const omnibinder::Buffer &) {
        SetError((int)err);                      /* -208 = IDL 不匹配 */
    });
```

> 与 roadmap "不要手写 topic 名" 的关系：那条针对的是"手写字符串 + 无 hash 校验"。这里用生成的 `TOPIC_IDL_HASH` 与生成的 `deserialize`，类型安全不打折，换来的是 `ERR_IDL_MISMATCH` 可见。

### 5.4 重试与状态

| 阶段 | 失败行为 | 退避 |
|---|---|---|
| `init` | 释放 runtime，记 `last_error` | 1,2,4,8,16,16,16,16,16,16 s（共 10 次 ≈111s） |
| `lookupService` | 同上 | 同上（**计入同一次计数**，不另开一套） |
| `subscribeTopic` | 同上 | 同上 |
| 全部用尽 | `state = FAILED`，**不再自动重试** | 等用户重播/切 URL |

`ERR_IDL_MISMATCH` 单独置文案："IDL 版本不匹配（板端 %s 与 PC 生成代码不一致）"。

### 5.5 关闭

```cpp
close():  stop = true;  if (rt) rt->stop();        // 打断 run()
          join drv; join ctl;                      // 顺序：先驱动后控制
          delete proxy; delete rt;                 // 析构里 delete impl_
          state = IDLE;
```

⚠ **不要**在 `close()` 里再调 `subscribeTopic/unsubscribeTopic`——`stop()` 之后 API 快速失败（`runtime.h:199` 注释）。取消订阅交给进程退出/runtime 析构。

## 9. OSD 模块（`ui_face_osd.c`）

### 9.1 对象结构（全池化，零热路径分配）

```
face_osd (透明容器, 父对象 = lv_screen_active(), 在 player 之后创建 → z 更高)

 └─ name_label     (lv_label, 唯一一个)
```

### 9.2 几何：视频显示矩形

```c
/* 1) 解码尺寸（本地可取，不依赖网络） */
int32_t aw = lv_image_get_src_width(player);
int32_t ah = lv_image_get_src_height(player);
/* 2) CONTAIN：等比缩放 + 居中留黑边 */
lv_area_t pc; lv_obj_get_coords(player, &pc);
float s  = LV_MIN((float)lv_area_get_width(&pc) / aw, (float)lv_area_get_height(&pc) / ah);
int32_t dw = (int32_t)(aw * s), dh = (int32_t)(ah * s);
int32_t x0 = pc.x1 + (lv_area_get_width(&pc) - dw) / 2;
int32_t y0 = pc.y1 + (lv_area_get_height(&pc) - dh) / 2;
/* 3) 画布(640x640, pad_top=140) → 屏幕坐标，无 enc 尺寸参与 */
px = x0 + (int32_t)(det->x1 / 640.0f * dw);
py = y0 + (int32_t)((det->y1 - 140.0f) / 360.0f * dh);
```

- 全部 `clamp` 到 `[x0, x0+dw] × [y0, y0+dh]`
- 换算后宽或高 `< 4px` 丢弃（与板端 `osd_face.cpp:75` 一致）
- 全屏切换后 `player` 的 coords 变了 → **OSD 在同一个 30ms 定时器里重算**，不需要额外钩子

## 10. Play 页接线

```
do_play(url) 成功
   ├─ host = parse_rtsp_host(url)        /* rtsp://192.168.10.168:554/live0 → 192.168.10.168 */
   ├─ face_open(host, 9900)
   └─ 状态灯 = 灰(Connecting)

stop_btn / ui_page_play_on_hide / 播放失败
   └─ face_close();  OSD 清空;  状态灯 = 灰

每 200ms（面板定时器里）
   ├─ st = face_state()
   ├─ 状态灯：CONNECTING 灰 / SUBSCRIBED 灰 / STREAMING 绿 / NODATA 黄 / FAILED 红
   └─ FAILED 时状态灯旁给「重试」按钮（点击 = face_close + face_open）
```

`parse_rtsp_host()` 规则：跳过 `://`，取到 `:` 或 `/` 为止；非法 URL 返回 NULL → 不启动会话（不重试）。

### 11.2 CMake 增量

```cmake
set(OMNIBINDER_ROOT "F:/git-clone/OmniBinder" CACHE PATH "OmniBinder 源码/构建根目录")

# mock 永远编
file(GLOB FACE_SOURCES "${PROJECT_SOURCE_DIR}/src/face/*.c")

# 有框架才编真实现（无框架自动降级到 mock，保证仓库在任意机器可编）
set(OMNIBINDER_LIB "${OMNIBINDER_ROOT}/build_win/target/lib/libomnibinder.a")
if(EXISTS "${OMNIBINDER_ROOT}/include/omnibinder/omnibinder.h" AND EXISTS "${OMNIBINDER_LIB}")
    message(STATUS "FaceResult: omnibinder 实现已启用（${OMNIBINDER_LIB}）")
    list(APPEND FACE_SOURCES
         "${PROJECT_SOURCE_DIR}/src/face/face_src_omnibinder.cpp"
         "${PROJECT_SOURCE_DIR}/src/face/generated/face_service.bidl.cpp"
         "${PROJECT_SOURCE_DIR}/src/face/generated/common_types.bidl.cpp")
    target_include_directories(lvgl PUBLIC
        "${OMNIBINDER_ROOT}/include"
        "${PROJECT_SOURCE_DIR}/src/face/generated")
    list(APPEND MAIN_LIBS "${OMNIBINDER_LIB}")
    add_compile_definitions(FACE_SRC_OMNIBINDER=1)
else()
    message(STATUS "FaceResult: 未找到 OmniBinder，仅编 mock 实现")
endif()
list(APPEND MAIN_SOURCES ${FACE_SOURCES})
```

注意：
- `.cpp` 由 CMake 自动识别（工程已是 `project(lvgl C CXX)`），无需额外配置编译器
- Windows 已链 `ws2_32`；C++ 运行时由 g++ 驱动自动带，不用显式 `-lstdc++`
- `libomnibinder.a` **不提交进仓**（988KB 二进制），路径由 cache 变量给出

### 11.3 两种构建配置都要能过

| 配置 | 结果 |
|---|---|
| 有 `OMNIBINDER_ROOT` | 编 mock + omnibinder；`face_source_active()` 返回 omnibinder |
| 无（或路径错） | 只编 mock；`face_source_active()` 返回 mock |

`face_source_active()` 用 `#ifdef FACE_SRC_OMNIBINDER` 选择，UI 代码零改动。

## 13. 风险与对策

| 风险 | 对策 |
|---|---|
| C++ 异常跨 C 边界（`extern "C"`） | 所有导出函数体 `try{...}catch(...){return -1}`；回调内不抛 |
| 回调线程碰 LVGL | 回调只写槽（`face_store_put`），UI 只读；代码评审时专门看这条 |
| `OmniRuntime` 复用导致 `ERR_ALREADY_INITIALIZED` | 每次重试 `new`，`close()` 里 `delete`（§5.5） |
| `stop()` 后 API 快速失败 | `close()` 里不再调任何框架 API，只 join + delete |
| OSD 坐标在非 16:9 流下变形 | 画布契约以 16:9 为前提（roadmap §6）；非 16:9 流本来也匹配不上 |
| 面板 25fps 刷新吃 CPU | 节流 5Hz + 分段 label（§7） |
| OSD 对象每帧增删 | 全池化，只改显隐与坐标（§9.1） |
| 播放器父对象是 screen、页面父对象是 content | OSD 容器也挂 screen，且在 player 之后创建（§9.1） |
