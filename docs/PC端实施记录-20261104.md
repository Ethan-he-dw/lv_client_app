## 3. 核心接口（供批次 2 与后续任务使用）

```c
/* 数据模型：任务差异只在 objs[] 与 attrs[]，UI 不认识具体字段 */
typedef struct {
    uint8_t task;  char task_name[16];  uint64_t seq, ts_us;
    uint16_t obj_count;  ivs_object_t objs[IVS_MAX_OBJS];   /* 16 */
    uint8_t attr_n;      ivs_attr_t   attrs[IVS_MAX_ATTRS]; /* 10 */
} ivs_result_t;

/* 源层：UI 只依赖这五个函数 */
int  ivs_open(const char *host, int port, const char *task);  /* "face" */
void ivs_close(void);
ivs_state_t ivs_state(void);          /* NODATA 由 3s 超时惰性推导 */
bool ivs_latest(ivs_result_t *out, uint32_t *ver);
const char *ivs_last_error(void);
```

**状态机**：`IDLE → CONNECTING → SUBSCRIBED → STREAMING`，超时 3s 显示 `NODATA`（不重试），重试用尽 → `FAILED`（面板出现 retry 按钮）。

**数据通路**：回调线程 → `ivs_store_put()`（覆盖 + version++）→ UI 定时器 `ivs_latest()`。不排队列，因为明确不需要与画面同步。

## 10. 直播流黑屏：根因与修复（2026-11-05）

### 10.1 现象

- 本地 mp4 能播；RTSP 直播黑屏
- FFmpeg 只报 `Failed reading RTSP data: End of file`
- CLI（ffmpeg 命令行）连读 15 秒完全正常，ffplay 同时在线也不影响 → **不是网络、不是并发数、不是解码器**

### 10.2 定位过程（值得复用）

本地起一个 TCP 代理（`127.0.0.1:8554 → 板端:554`），记录双向报文，看到客户端自己的行为：

```
OPTIONS → 200
DESCRIBE → 200 (SDP)
SETUP   Transport: RTP/AVP/UDP...   → 200 (Session: 20560)
PLAY    → 200
（约 2 秒后）
PAUSE   CSeq: 5     ← 客户端自己发的
PAUSE   CSeq: 6
```

**根因**：`lv_ffmpeg.c` 在 `LV_FFMPEG_PLAYER_CMD_START` 里无条件执行

```c
av_seek_frame(fmt_ctx, 0, 0, AVSEEK_FLAG_BACKWARD);
```

对 RTSP 直播流，解复用器用 **PAUSE + PLAY** 实现 seek；服务端被 PAUSE 后停止推流，后续 `av_read_frame` 直接 `AVERROR_EOF`。文件可 seek，所以本地播放不受影响——这解释了"文件能播、直播不能播"。

### 10.3 修复

`IVS-PATCH(3/3)`：仅在输入可 seek 时才回绕（START 与 STOP 两处）：

```c
if(fmt_ctx->pb != NULL && (fmt_ctx->pb->seekable & AVIO_SEEKABLE_NORMAL)) {
    av_seek_frame(fmt_ctx, 0, 0, AVSEEK_FLAG_BACKWARD);
}
```

验证：`End of file` 出现 **0 次**，解码 162 个 slice，画面正常。

### 10.4 附带修复

| 项 | 说明 |
|---|---|
| NODATA 判定 | 原逻辑只在"收到过数据后超时"才转 NODATA；订阅成功但从未收到数据会永远停在 SUBSCRIBED。改为记录订阅时刻，3s 无数据同样转 NODATA |
| 面板文案 | 从未收到数据时显示 `st=NODATA (no data yet)`，不再显示无意义的 `(0s)` |
| 非 RTSP 输入 | 本地文件/图片不再启动识别会话（原先会把路径首段当作 host 去连，白等 111s） |

## 11. 真正的根因：框架 topic 发布端绕过了 register host（2026-11-05）

板端三项检查全部通过：

```
FACE_REGISTER_HOST=192.168.10.168          # 进程环境里有
grep -ac "advertise host" .../face_proc → 1  # 二进制含 D2
[face] advertise host=192.168.10.168 (env FACE_REGISTER_HOST=set)  # 日志确认生效
```

PC 仍收到 `Topic FaceResult publisher at 127.0.0.1:PORT`。原因在框架：

| 位置 | 代码 | 结果 |
|---|---|---|
| `runtime_service.cpp:79`（service 注册） | `resolveRegisterHost(service, listenerAdvertiseHost())` | ✅ 用 board IP |
| **`runtime_topic.cpp:132`（首次 publishTopic）** | **`listenerAdvertiseHost()`** | ❌ 恒为 127.0.0.1 |
| **`runtime_sm.cpp:434`（SM 重连恢复）** | **`listenerAdvertiseHost()`** | ❌ 恒为 127.0.0.1 |

即：**service 级地址尊重 `setRegisterHost`，topic 发布端地址完全不尊重**。所以"PC 能 lookup 到服务、但拿到的发布端永远是回环"，与板端配置无关。

### 修复（框架侧，两处）

```cpp
// runtime_topic.cpp:135
pub_info.host = resolveRegisterHost(entry->service, listenerAdvertiseHost());

// runtime_sm.cpp:436
pub_info.host = resolveRegisterHost(sit->second->service, listenerAdvertiseHost());
```

未设置 register host 时 `resolveRegisterHost` 回落 `normalizeAdvertiseHost(listener)`，与改动前行为一致，对既有使用者无影响。

### 对既有文档的更正

`setRegisterHost.md` v2 的结论"只在应用侧设一次 register host 即可跨机"**不完整**：它只覆盖 service 注册，没有覆盖 topic 发布端。该缺陷修复前，跨机 topic 订阅在任何配置下都不可能成功。

## 12. 直播延迟与放大块状（2026-11-09）

### 12.1 现象与实测

| 问题 | 表现 |
|---|---|
| 延迟 | 播放 RTSP 后延迟明显，且随时间增长 |
| 块状 | 画面边缘块状；ffplay 同流无此问题 |
| DATA 按钮 | 点一次画面变大且面板被盖住；再点画面不变 |

### 12.2 根因

| # | 根因 | 证据 |
|---|---|---|
| 1 | `apply_player_layout()` 用 `s_panel_was_visible`（只在全屏分支赋值）强制恢复面板，撤销了 Data 的切换 | 自检：修复前 `1/1400 → 0/1400`，修复后 `1/990 → 0/1400 → 1/990` |
| 2 | LVGL 的 SDL 后端未设 `SDL_HINT_RENDER_SCALE_QUALITY`，默认 nearest，640×360 放大到 990×570 | 设 `SDL_RENDER_SCALE_QUALITY=linear` 后画面变平滑 |
| 3 | 取帧模型"每 tick 一帧、无 framedrop"：产能=流速率，零余量，积压不可逆 | 实测仅 22fps（流 30fps），每秒欠 8 帧 ≈ 延迟 +0.26s/s |

### 12.3 修复

| 改动 | 位置 |
|---|---|
| `SDL_SetHint(SDL_HINT_RENDER_SCALE_QUALITY, "linear")`（须在 `sdl_hal_init` 前） | `src/main.c` |
| 面板恢复改为一次性标志 `s_restore_panel_after_fs` | `src/ui/ui_page_play.c` |
| RTSP 传输可配（默认 **UDP**，`IVS_RTSP_TRANSPORT=tcp` 可切回）+ `fflags=nobuffer` | `lv_ffmpeg.c` `IVS-PATCH(2/3)` |
| 解码器 `flags=+low_delay` | `lv_ffmpeg.c` `IVS-PATCH(5)` |
| 追帧丢帧：以首帧为基准比较 pts 与墙钟，落后 >200ms 丢帧继续追，每 tick 最多追 8 帧 | `lv_ffmpeg.c` `IVS-PATCH(4)` |

> UDP 之所以能改回来：当初 UDP 报 `Invalid data` 的根因是 START 时误 seek 导致服务端 PAUSE（已由 `IVS-PATCH(3/3)` 修复），与传输方式无关。

### 12.4 效果

| 指标 | 修复前 | 修复后 |
|---|---|---|
| 帧率 | 22 fps | **29–30 fps** |
| 断流 EOF | 0（TCP） | 0（UDP） |
| 丢帧 | 无机制 | 默认不触发（能跟上）；阈值 1ms 强制测试可触发且画面正常 |
| 画面 | 边缘块状 | 平滑 |
| DATA 按钮 | 失效 | 正常 |

可调参数：`IVS_SYNC_MAX_LAG_MS`（默认 200，现场弱机可调大）、`IVS_RTSP_TRANSPORT`（udp/tcp）。

## 13. 追帧失效与 UDP 花屏（2026-11-09 下午）

### 13.1 追帧从未生效：落后量符号写反

实测 `lag` 恒为**负**且持续扩大（40 秒到 −5.2 秒），而判定条件是 `lag > 200ms`，因此**丢帧分支一次都没执行**——"延迟自愈"实际不存在，延迟一路累积到数秒。

修正前后（live2 / TCP）：

| | behind 取值 | 丢帧 |
|---|---|---|
| 修正前 | 0 → −5200ms（持续扩大） | 0 次 |
| 修正后 | 稳定 **200–211ms** | 55 秒内 361 次 |

```c
/* 落后量 = 墙钟已过 - 帧时间轴已过 */
const int64_t behind = (now_ms - base_wall) - (pts_ms - base_pts);
if(behind > threshold) { drop; continue; }
```

### 13.2 竖向条带花屏 = UDP 丢包

| 实验 | 结果 |
|---|---|
| live2 + UDP（默认） | 人脸出现竖条 + 绿紫偏色（缺 slice） |
| live2 + TCP，110 秒 | **完全干净** |
| 0 次解码错误、0 次 EOF | — |

原因：消费速率（22–29fps）略低于码流 30fps，UDP 内核接收缓冲被撑爆 → 丢 RTP 包 → 解码器缺 slice → 条带。

**处置：默认传输改回 TCP**（`IVS_RTSP_TRANSPORT=udp` 可切回）。TCP 无丢包，积压带来的延迟由 13.1 的追帧钳在 ~200ms。

### 13.3 界面/进程相关的澄清

- 之前多次"进程消失"实为**后台启动方式被回收**，前台跑满 100 秒（timeout 124）正常退出；`%LOCALAPPDATA%\CrashDumps` 无当日 dump → 非崩溃
- `LV_USE_DRAW_SDL=1` 实验：CPU 76%→17%，但视频全黑（SDL 纹理缓存不刷新"内容每帧变"的可变图像），已回退。结论：缩放成本确实在软件路径，但该开关不能直接打开

## 14. 面板显隐状态拆分 + 双击失效（2026-11-09）

### 14.1 现象

- 退出全屏后播放器仍是全宽，面板被压在下面（此前靠临时加 `ui_ivs_panel_toggle()` 绕过）
- 双击有时无反应，且 `LV_LOG` 也不打印

### 14.2 根因

| 问题 | 原因 |
|---|---|
| 退出全屏后仍是宽屏 | `apply_player_layout()` 先算 `video_width()` 再恢复面板 ⇒ 宽度按"面板隐藏"算成全宽 |
| 双击时灵时不灵 | OSD 叠加层里的**人脸框/关键点/姓名标签默认可点击**，光标落在框上时点击被它们吃掉，播放器收不到 `DOUBLE_CLICKED` |
| 临时 toggle 有副作用 | 面板"用户选择"与"全屏临时隐藏"共用一个变量，双击会改写用户偏好 |

### 14.3 修复

1. 状态拆分：`s_panel_user_visible`（只由 Data 按钮改）；全屏只做临时隐藏，退出按用户选择恢复
2. **先恢复面板可见性，再计算播放器宽度**（顺序修正）
3. OSD 子对象（框/点/标签）全部 `lv_obj_set_clickable(x, false)`，不再拦截点击
4. 双击只切全屏，不再 toggle 面板
